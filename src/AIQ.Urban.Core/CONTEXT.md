# AIQ.Urban.Core — Domain Context

## Purpose
Pure city-modelling domain logic. Models buildings, transit networks, parcels, zones, topography, and vegetation for architectural site-planning in Rhino.

## Implemented
1. `Models/UrbanElements/UrbanElement.cs` — base class with `Guid Id`
2. `Models/UrbanElements/Transit.cs` — Transit subclass, Outline calculated eagerly
3. `UrbanModel.cs` — singleton, `List<Transit> Transits`, `AddTransit()`, `List<Building> Buildings`, `AddBuilding()`
4. `Rhino/Commands/AddTransit_AIQUrban.cs` — transit command
5. `Models/GeometryElements/Profile2D.cs` — planar curve wrapper, XY-validated
6. `Models/Use.cs` — `record` with `string Name` + `Color`
7. `Models/FloorPlate.cs` — `Profile2D Outline` + `Use`, per-storey footprint
8. `Models/UrbanElements/Building.cs` — constructor takes `(Curve footprint, double typicalFloorHeight, int floorCount, Use use)`, eagerly computes envelope (solid Brep extrusion) and floor plates (duplicated + translated). Footprint validated by `ValidateFootprint()`: checks planar, reverses if normal points down.
9. `Models/Zone.cs` — `IUrbanElement` with `Polygon2D Boundary` and `string Name` properties. `GetContainedElements(UrbanModel)` returns all `IUrbanElement`s whose `GetRepresentativeCenter()` falls inside the zone boundary. Never returns other Zones.

## Design Constraints

### Nullable Reference Types
- All AIQ.Urban projects have `<Nullable>enable</Nullable>`. Use `?` to mark types that can legitimately be null (return values, parameters). If something lacks `?`, assume it is not null — skip null checks.

### Dependency Rule
- **AIQ.Urban.Core** references RhinoCommon as its geometry kernel (Curve, Brep, Mesh, Point3d, Transform, etc.)
- **AIQ.Urban.RhinoPlugin** references AIQ.Urban.Core + RhinoCommon separately for the Rhino interface
- Core depends on **no** other solution projects (especially not the old `ArchSitePlan.*` or `BHoM.*` projects)

### Model State
- `UrbanModel` is a singleton in AIQ.Urban.Core holding all `IUrbanElement`s. It is the single source of truth for the in-memory model. Rhino doc serialization is a future concern.
- Access pattern: static `UrbanModel.Instance` property with lazy initialization.
- Operation methods live directly on `UrbanModel` (e.g. `urbanModel.AddTransit(transit)`).
- Directly added elements: Transits, Buildings, Parcels, Zones — each stored in their own `List<T>`.
- Derived geometry (computed from elements, not directly added by commands):
  - `List<(Profile2D Profile, TransitType Type)> TransitSurfaces { get; }` — populated by `TransitSurfaceUnioner` after each transit mutation.
  - `List<Parcel> Parcels { get; }` — cleared and regenerated by `RecalculateParcelsStep` from `TransitSurfaces` holes.

### Pipeline
- **RhinoUrbanModelPipeline** in `src/AIQ.Urban.Rhino/Pipeline/` orchestrates multi-step sync between the Rhino doc and UrbanModel.
- Steps accumulate in a single ordered list, not category buckets. At `Run()` time each step's returned GUIDs are routed to the delete, edit, or add bucket based on its marker interface (`IDeleteUrbanElementsStep`, `IEditUrbanElementsStep`, `IAddUrbanElementsStep`). A step may implement multiple interfaces so its GUIDs flow to multiple buckets.
- Eager execution: when a command adds/modifies an element, the pipeline automatically recalculates all dependent elements. E.g. `AddTransit_AIQUrban` runs: delete old transits → add new transits → union transit surfaces → recalculate parcels from holes.
- RhinoPlugin commands collect user input, convert Rhino types → Core types, call into the pipeline, then read back from `UrbanModel` to display.

### IUrbanElement Hierarchy
- `IUrbanElement` is the base interface for all urban elements. Methods: `List<Guid> GetGeometryIds()`, `Point3d GetRepresentativeCenter()`. Implementations: Building, Transit, Parcel, Zone, FloorPlate.
- `GetRepresentativeCenter()` returns a single point used for spatial queries: centroid of lowest floor plate (Building), midpoint of centerline (Transit), centroid of outline (Parcel, FloorPlate, Zone).
- No composite nesting — Zones do not contain other Zones.
- `Metrics` subtypes (ZoneMetrics, AreaMetrics, etc.) reference model elements but are not `IUrbanElement`s.

### Folder Structure
- `Models/` — Use, Zone, Node, and other non-UrbanElement model types
- `Models/UrbanElements/` — concrete IUrbanElement implementations (Building, Transit, Parcel, FloorPlate)
- `Models/GeometryElements/` — geometry wrappers (CurveElement, Profile2D, Polygon2D)
- `Geometry/` — geometry helper utilities
- Project root — UrbanModel and top-level orchestration

### Geometry Approach
- `Profile2D : IGeometryElement<Curve>` — wraps a Rhino Curve, enforces planar at consistent Z (no Z variation). Used for FloorPlate outlines and Parcel2D outlines.
- `IGeometryElement<T>.Id` is settable — the Rhino layer overwrites placeholder IDs with real Rhino ObjectIds after baking (see `RhinoUrbanModelPipeline.BakeNewUrbanElements`).
- `Node` is a new custom class for graph nodes. Future consideration: replace with topologyNet when TransitGraph is fully designed.
- RhinoCommon types (Curve, Brep, Mesh, Point3d, Transform) used for all 3D geometry.

## Domain Glossary

### Use
A semantic label with visual feedback. `string Name` + `Color` (System.Drawing.Color). Stored as a `record` in `Models/Use.cs`. Not an enum — instances are created at runtime (e.g. "Residential", "Commercial", "Retail", "Industrial", "MixedUse", "Public", "Park", "Parking", "Utility").

### Building
A constructed structure. Has a collection of `FloorPlate`s and a `Brep Envelope` representing the outer shell. Added via `UrbanModel.AddBuilding(Building)`.

### FloorPlate
A single storey of a Building. Defined by a `Profile2D Outline` and a `Use`. Each storey has its own footprint shape. Floor elevation is determined by the Profile2D curve's plane Z.

### TransitType
Enum: `Road`, `Railway`, `CyclePath`, `Pedestrian`, `Waterway`.

### Transit
A linear transportation corridor of a given `TransitType`. `Outline` is calculated eagerly in the constructor via a private method. Properties:
- `Curve Centerline` — path along the corridor (must be planar at a consistent Z)
- `Curve Outline` — closed boundary curve formed by offsetting centerline ±width/2 with straight-line end caps representing the full right-of-way
- `double Width`
- `bool IsOnGround`
- `List<TransitNode> OrderedNodes`

### TransitSurface
A unioned planar Brep (`Profile2D`) representing the merged right-of-way of all `Transit` elements of the same `TransitType`, irrespective of individual widths. Stored in `UrbanModel.TransitSurfaces` as `List<(Profile2D Profile, TransitType Type)>`. Produced by `TransitSurfaceUnioner` in the RhinoPlugin pipeline. Used for clean merged geometry (presentation, area calcs).
- **Geometry**: Uses `Brep.CreateBooleanUnion(outlineBreps, tolerance)` to merge all per-type outlines, then wraps result boundary into a `Profile2D`.
- **Scope**: Recomputes all transits of each type from scratch on every pipeline run.
- **Known gap**: When transits are deleted/modified, previously baked unioned surfaces remain as orphans in the Rhino doc — no cleanup logic yet.

### TransitGraph
Collection of `TransitNode`s forming a connected network.

### TransitNode
A `Node` with `List<Node> Neighbours`. Junction/intersection in a transit network.

### Parcel2D
A 2D land parcel with a `Polygon2D Outline` and a `Use`. Stored in `UrbanModel.Parcels` — cleared and regenerated on each transit change by `RecalculateParcelsStep`. Parcels are derived from the holes in each `TransitType`'s unioned surface (`TransitSurfaces`). Default `Use` is `DefaultUses.Public`. No deduplication is performed if multiple transit types produce overlapping holes.

### Parcel3D
A 3D parcel extruded from a `Parcel2D FlatParcel` plus a `Mesh ProjectedParcel` (e.g. terrain-projected).

### Zone
An `IUrbanElement` with a `Polygon2D Boundary` and a `string Name`. A named spatial container (e.g. "Downtown", "Park") that can query which model elements fall within its boundary. `GetContainedElements(UrbanModel)` tests each element's representative point (centroid of lowest floor plate for buildings, midpoint of centerline for transit, centroid of outline for parcels) against the boundary. Never returns other Zones. Layer: `AIQ Urban::Zone::{Name}`.

### Parcel (group)
A `ModelGroup` attached to a `Parcel2D Host`. Groups ModelElements that sit on that parcel.

### Site
A `ModelGroup` — top-level container for the entire project. No extra properties yet.

### ModelGroup
*(deferred — not yet implemented)* Base grouping container. `List<ModelElement> Elements` + `string Name`.

### ProjectMetrics
Aggregate metrics for the entire urban model. Contains `List<BuildingMetrics>`, `List<ParcelMetrics>`, and computed roll-ups (`TotalBuiltUpArea`, `TotalLandArea`, `OverallFAR`, `OverallCoverageRatio`, `BuildingCount`, `ParcelCount`, `AreaPerUse` by use name). Stored on `UrbanModel.ProjectMetrics` — set by `ProjectMetricsCalculator` after pipeline runs. Defined in `Models/Metrics/ProjectMetrics.cs`.

### ProjectMetricsCalculator
Static utility in `Models/Metrics/ProjectMetricsCalculator.cs`. Reads `UrbanModel.Buildings` and `UrbanModel.Parcels`, computes `BuildingMetrics` for each building, determines building-to-parcel containment via spatial query (point-in-polygon on XY plane), computes `ParcelMetrics`, and stores the result on `UrbanModel.ProjectMetrics`.

### TopoMesh
A terrain mesh. Wraps a Rhino `Mesh`.

### Vegetation
A `PointObject` with `Transform Base` and `Geometry GeometryAtOrigin`. A placed plant/object repeated from a template.

### Metrics
Abstract base for computed analytics on a `ModelGroup`. Concrete subtypes:
- **ZoneMetrics**, **AreaMetrics**, **RadiationMetrics**, **TransitMetrics**, **ParcelMetrics**
