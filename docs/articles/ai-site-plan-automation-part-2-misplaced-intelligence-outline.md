# AI For Site Plan Automation: Misplaced Intelligence

Part 1 argues that AI cannot site plan properly if the plan is made of orphaned geometry.

The solution is a living site model.

Part 2 should explore the next problem:

Misplaced intelligence.

This means asking one type of intelligence to do every type of work.

There are two common versions of this mistake:

1. Expecting parametric scripts to solve the whole planning process
2. Expecting AI to know and do everything like magic

Both approaches are useful.

Both also fail when pushed too far.

## Core Claim

The best approach is not purely parametric design and not purely AI.

The best approach is human judgment + deterministic tools + AI assistance, all acting through a living site model.

## Antagonist 1: Over-Specialised Parametric Scripts

Parametric tools are excellent when the problem is well defined.

They are good at:

1. Offsetting roads
2. Generating floor plates
3. Calculating FAR, coverage, built-up area and use mix
4. Checking constraints
5. Repeating operations quickly
6. Producing variations inside a defined design logic

But they often become too narrow.

The script works beautifully for the problem it was written for.

Then the brief changes.

The site changes.

The client asks a different question.

The designer wants to try something that does not fit the structure of the script.

This creates technique tunnel vision.

The tool is powerful, but the workflow becomes trapped inside the assumptions of the tool.

Key line:

> Parametric tools are excellent at answering questions that have already been formalised. They are weaker at deciding which question should be asked next.

## Antagonist 2: Over-Generalised AI Expectations

The opposite mistake is expecting AI to do everything.

Give it a prompt.

Ask it to understand the site.

Ask it to generate the plan.

Ask it to calculate the metrics.

Ask it to judge the design.

Ask it to know the constraints.

Ask it to make the right tradeoffs.

This is also unrealistic.

AI is excellent at:

1. Interpreting language
2. Understanding intent
3. Comparing options
4. Explaining tradeoffs
5. Helping navigate ambiguity
6. Choosing which tool might be useful next

But AI should not be expected to directly own:

1. Geometric validity
2. Planning calculations
3. Object identity
4. Downstream model updates
5. Regulatory compliance
6. Final design judgment

Key line:

> AI is useful when it has tools and a model to act through. It is dangerous when it is treated as the model, the tool and the designer at the same time.

## The Better Split

Each part of the workflow should do what it is good at.

| Participant | Best role |
| --- | --- |
| Human designer | Sets goals, judges quality, resolves tradeoffs and makes taste decisions |
| Parametric tools | Perform exact operations, calculations, propagation and checks |
| AI | Interprets intent, proposes actions, connects tools and explains consequences |
| Living site model | Stores the shared truth of buildings, parcels, roads, zones, uses and metrics |

The living site model from Part 1 makes this possible.

Without it, AI and parametric tools are still acting on disconnected drawings.

With it, both can act on the same meaningful planning objects.

## Example Workflow

A user asks:

"What happens if we add two floors to the residential buildings near the main road, keep ground-floor retail, and preserve the open-space target?"

In the workflow:

1. The human sets the goal and reviews the result.
2. AI interprets the request.
3. Deterministic tools adjust the building floors and recalculate the metrics.
4. The living site model stores the updated buildings, parcels, uses and metrics.
5. AI explains the consequences and suggests alternatives.

This is very different from asking AI to generate a pretty image of a masterplan.

It is also different from locking the designer inside one parametric script.

It is a connected workflow.

## Suggested Structure For Full Article

1. Open by saying the debate should not be AI vs parametric design.
2. Explain why parametric tools are powerful but narrow.
3. Explain why AI is flexible but cannot do everything by magic.
4. Name the problem as misplaced intelligence.
5. Introduce the better split: human judgment, deterministic tools, AI assistance and living model.
6. Use the example workflow above.
7. Close by saying that the future is not AI replacing architects. It is AI helping operate a model that architects can trust.
